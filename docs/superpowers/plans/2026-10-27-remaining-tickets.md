## 1. #5 — Ссылка на вариант и «Полная версия — скоро»

- **Новый модуль `js/link.js`**: параметры вкладки ⇄ часть адреса после `#`. Формат общий: `#naves&width=3000&height=2000`. Мангал и печь потом добавят свои ключи.
  - Чтение: каждое значение проверяется по LIMITS вкладки (число, в диапазоне, кратно шагу). Мусор и обрезанные ссылки → готовый пример, без ошибок в консоли.
  - Только вкладка (`#mangal`) — открыть её с готовым примером. Это же нужно #11 для карточек лендинга.
- **Кнопка «Ссылка на вариант»** под результатом. Копирует через `navigator.clipboard`. Если браузер не дал — показать ссылку в поле, выделенной, «скопируйте вручную». Под кнопкой «Ссылка скопирована».
- **Кнопка «Открыть полную версию»**: адрес в одной константе (`FULL_VERSION_URL = ''`). Пусто → «Полная версия — скоро», `disabled`.
- Мелочь: в CLAUDE.md поправить «demo.html — её пока нет».
- Проверка: ссылка в новой вкладке → тот же навес; битые ссылки (`#naves&width=abc`, `#naves&width=99999`, `#xyz`) → пример; копирование на 390 px.

**Решено (Виталий, 27.10.2026):** ссылка открывает вариант сразу с результатом «В производство».

## 2. #6 — Мангал (самый большой)

Сначала **отдельным коммитом — подготовка `demo.js` к нескольким вкладкам**. Сейчас он написан под навес (id `naves-*`). Нужна общая «вкладка»: описание параметров (ползунок / переключатель / выбор) → расчёт → эскиз → результат → лист → кнопки. Навес переводится на неё без изменения вида, проверяется, коммитится.

Потом сам мангал:
- **`js/mangal.js`** — расчёт: листовые детали с развёртками (прямоугольник + отверстия + линии гиба, всё в мм), масса по толщине (сталь 7850 кг/м³, лист по ГОСТ 19903 в справочнике `metal.js`), покупки (болты М16 для ножек, колёса), площадь металла и оценка листов 1250 × 2500 при заполнении 70 % с пометкой «оценка».
- Источник: `C:\dev\metal-designer\mangal\js\params.js` (L1=800, W=420, H1=130, TOPH=970, колесо TOR SC 42 Ø100 высота 126, площадка 150×150×6), `parts.js`, `cut.js`, `dxf.js`. Код там на глобальных переменных, в см и с THREE.js — **формулы переносим, код пишем заново** в стиле песочницы, в мм.
- **`js/sketch-mangal.js`** — вид спереди и сбоку с размерами, как у навеса.
- **Развёртки** на странице: маленький SVG на каждую деталь с размерами. Общий рисовальщик `js/unfold.js`, его потом возьмёт печь.
- Лист чертежа: спецификация уже общая, в «Размер» пишем `800 × 420 × 4`.
- Ссылка на вариант: ключи мангала в `link.js`.

**Решено (Виталий, 27.10.2026):**
- Готовый пример — металл 5 мм. Переключатель 3/4/5 мм остаётся, его требует тикет.
- Ножки «обычные»: один вид ножки, без выбора материала. Переключатель «на болтах / вваренные» остаётся по тикету. Какой профиль — взять из Metal Designer и показать в плане #6.

- Состав минимальный: 2 боковины, дно, 2 торца, ножки, отверстия поддува, колёса с площадками. Без колосника, перегородки, задвижек и ручки. Готовый пример 800 × 420 × 970, 5 мм, поддув есть, ножки на болтах, без колёс.

Риск: тикет большой. Если в одну сессию не влезает — делим: 6a расчёт + эскиз + развёртки, 6b лист, ссылка и мобильная вёрстка.

## 3. #7 — DXF мангала

- **`js/dxf.js`** — общий модуль: детали `{ name, loops, circles, bends }` в мм → текст DXF R12 (AC1009), слои CUT и BEND. LINE/POLYLINE для контуров, CIRCLE для отверстий. Все детали в одном файле в ряд с зазором 20 мм: без библиотек архив не собрать, а один файл цеху удобнее.
- Скачивание через Blob, как PNG листа. На айфоне — та же подсказка «Поделиться → Сохранить в Файлы».
- Проверка у меня: разбор файла скриптом (пары код/значение, замкнутые контуры, размеры = развёрткам). У Виталия: LibreCAD.

**Вопрос:** подписи деталей (TEXT) в DXF класть на отдельный слой TEXT или не класть совсем? По тикету слоёв только два. Предлагаю отдельный слой TEXT: его легко выключить, а без подписей цех запутается в деталях.

## 4. #8 — Печь под казан + DXF

- **`js/pech.js`**, **`js/sketch-pech.js`**, развёртки через `unfold.js`, DXF через `dxf.js`, ссылка через `link.js`. Всё общее уже готово, поэтому тикет в основном про конструкцию.
- Из Metal Designer: плита 450 × 450 с проёмом Ø390, кольца Ø300/Ø210/Ø120 (`RINGS`), казаны `KZS` (6/8/10/12 л — какой проём снимается), печь внутри 440, длина топки 600, труба 60 × 60 (`CH`), отсекатель пламени (`fb`), колосник, дверца, поддувало с шибером.
- Казан меняет только кольца в покупках и подпись на чертеже, корпус и DXF не трогает.
- Покупки: плита с кольцами, колосник, петли.

**Вопрос:** колосник покупной (по тикету в списке покупок) — значит, в DXF его нет, верно? В Metal Designer он режется из листа.

## 5. #9 — Ваше изделие

Самый рискованный по удобству на телефоне. Предлагаю **начать с прототипа** (скил `prototype`): одна страница-черновик, проверить, как ставить линии пальцем и двигать/увеличивать фото. Потом уже вкладка.

- **`js/trace.js`**: фото через `<input type="file" accept="image/*">` → `URL.createObjectURL`, никуда не уходит. Поверх фото SVG с линиями. Два режима: «двигать фото» (перетаскивание, щипок и кнопки ±) и «ставить линию» (тап — начало, тап — конец, привязка к концам соседних линий).
- Список линий: длина по масштабу, поле «вписать вручную» (перекрывает масштаб), кнопка «эта линия — известная длина», удалить.
- Профиль трубы — один выбор из справочника `metal.js`.
- «В производство»: детали-трубы → `cutting.js` (раскрой из #3), масса, лист: эскиз — линии в мм без фото.
- Тексты: «Фото остаётся на вашем телефоне…», про плоскую раму и компьютер, блок «Нужного нет или есть 3D-модель?» с Telegram https://t.me/SHVA_1984. Ссылки на вариант нет.

**Вопрос:** куда девать трубы длиннее 6 м (ворота 4 × 2 м — нет, а забор бывает)? `cutting.js` уже отдаёт их отдельно с пометкой «варить из двух». Достаточно?
