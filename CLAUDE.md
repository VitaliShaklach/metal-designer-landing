# Metal Designer для цехов: лендинг и MVP

## Что это за проект

Учебный проект Виталия. Идея: цех лазерной резки и сварки сам, прямо при клиенте, собирает эскиз изделия с размерами и сразу получает производственный проект: длины реза, раскрой, массу, DXF под лазер, чертёж в PDF. Сейчас за такой эскиз цех платит проектировщику на стороне ещё до того, как клиент сказал «да».

Проект состоит из двух частей:
- **Лендинг** (`index.html`) за 10 секунд объясняет это владельцу цеха. Он уже опубликован.
- **MVP-песочница** (`demo.html`, строится по задачам). Четыре вкладки: навес, мангал, печь под казан, ваше изделие. Человек двигает ползунки, жмёт «В производство» и видит настоящий расчёт.

Подробности и все решения лежат в документах дизайна в `docs/superpowers/specs/`. Перед любой задачей прочитай нужный:
- `2026-10-20-landing-design.md` — лендинг;
- `2026-10-22-mvp-sandbox-design.md` — песочница.

Жёсткие рамки, потому что сайт живёт на GitHub Pages:
- только HTML, CSS и JavaScript в браузере;
- без сервера, базы данных, API-ключей и платных сервисов;
- без библиотек и шрифтов из интернета;
- страница работает на телефоне шириной 390 px без горизонтальной прокрутки.

## Что где лежит

- `index.html` — лендинг, одна страница, стили внутри.
- `demo.html` — песочница, модули в `js/`: расчёты отдельно от эскизов и интерфейса (`demo.js`).
- `docs/superpowers/specs/` — документы дизайна. В `assets/` лежит фото навеса, по которому рисуется навес в песочнице.
- `docs/agents/` — настройки для скилов: где задачи, какие метки, где словарь проекта.
- `.superpowers/` — наброски с брейнштормов. В git не попадают.

## Как сайт публикуется

GitHub Pages собирает сайт из ветки `master`, из корня репозитория. После каждого `git push` он пересобирается примерно за минуту и открывается по адресу https://vitalishaklach.github.io/metal-designer-landing/. Репозиторий публичный: всё, что попадает в `master`, видят все.

## Как мы работаем

Одна задача в GitHub Issues — одна новая сессия Claude Code. В начале сессии берём задачу по номеру, читаем её и нужный документ дизайна, делаем, проверяем на десктопе и на телефоне. В конце коммит, push и закрытие задачи.
