# Metal Designer для цеха: лендинг и MVP

## Что это за проект

Учебный проект Виталия. Идея: цех лазерной резки и сварки подгоняет изделие под клиента прямо при нём и сразу получает производственный проект: длины реза, раскрой, массу, DXF под лазер, чертежи в PDF. Сейчас за такой проект цех платит проектировщику на стороне ещё до того, как клиент сказал «да».

Проект состоит из двух частей:
- **Лендинг** (`index.html`). Первый экран — живой 3D-мангал из движка `md/`: длина, ширина, высота ползунками, толщина кнопками 2–6 мм. Ниже — размеры, раскрой и масса, DXF, листы А3, карты деталей А4, «Сейчас / с Metal Designer», «Как работаем» и контакты. Виталий кидает ссылку владельцу цеха после звонка.
- **MVP-песочница** (`demo.html`). Четыре вкладки: навес, мангал, печь под казан, ваше изделие. С лендинга на неё ссылки нет.

Подробности и все решения лежат в документах дизайна в `docs/superpowers/specs/`. Перед любой задачей прочитай нужный:
- `2026-10-29-landing-v2-design.md` — лендинг (спека 20.10 заменена ею, только для истории);
- `2026-11-01-landing-lynx-editor-link-design.md` — дополнение к ней: рысь, «Мангал | Рысь», переход в редактор; где расходятся — действует оно;
- `2026-10-22-mvp-sandbox-design.md` — песочница.

Жёсткие рамки, потому что сайт живёт на GitHub Pages:
- только HTML, CSS и JavaScript в браузере;
- без сервера, базы данных, API-ключей и платных сервисов;
- библиотеки и шрифты — только копиями в репозитории (`vendor/`, `fonts/`); при открытии страницы ничего не грузится со сторонних серверов;
- страница работает на телефоне шириной 390 px без горизонтальной прокрутки.

**`C:\dev\metal-designer` (хобби-сайт) не трогаем**: только читаем и копируем оттуда сюда. Никаких правок, коммитов и запусков, которые пишут туда файлы.

## Что где лежит

- `index.html` — лендинг.
- `md/` — движок мангала и страница лендинга. `params, parts, model, dims, cut, dxf` — копия из `C:\dev\metal-designer\mangal\js` с правками под переменные размеры и толщину; `defaults.js` — настройки лендинга; `stats.js` — цифры панели; `link.js` — ссылка с размерами; `landing.js` и `controls.js` — страница и управление; `views.js`, `sheet-kit.js`, `sheets.js`, `nest.js`, `cards.js` — листы А3, раскрой на лист, карты А4.
- `vendor/three/` — three.js r128, OrbitControls, CSS2DRenderer (локальные копии с лицензией).
- `fonts/` — Oswald, Golos Text, JetBrains Mono в woff2 и лицензии OFL.
- `css/` — `landing.css` (страница) и `md.css` (блоки движка).
- `img/og.png` — карточка ссылки для мессенджеров, 1200 × 630.
- `lynx/` — рысь для первого экрана, готовые файлы одной версии: `model.json` (точки и грани), `stats.json` (плитки цифр), `photo-1..3.jpg` (было), `rework.jpg` (гранёная модель со швами), `poster.jpg` (3D картинкой), `nest.jpg` и `sheet.jpg` (первый лист раскроя и чертежей). Руками не правим — собирает `tools/lynx-capture.js`.
- `tools/lynx-capture.js` — сборщик `lynx/` из `C:\dev\metal-designer\art\private\lynx.html` (только для разработки, на сайт не влияет). `C:\dev` только читает: отдаёт его через `python -m http.server` на 127.0.0.1 и снимает страницу в Playwright.
- `demo.html` — песочница, модули в `js/`: расчёты отдельно от эскизов и интерфейса (`demo.js`).
- `tests/` — автотесты: `unit/` (расчёты, ссылка, листы, карты в Node), `e2e/` (страница в браузере), `engine.js` и `golden.json` (стенд движка и эталон цифр), `serve.py` (локальный сервер).
- `package.json`, `playwright.config.js` — только для тестов; на сайт не влияют, `node_modules/` в git не попадает.
- `docs/superpowers/specs/` — документы дизайна; `docs/superpowers/plans/` — планы работ.
- `docs/agents/` — настройки для скилов: где задачи, какие метки, где словарь проекта.
- `.superpowers/` — наброски с брейнштормов. В git не попадают.

## Как проверять

Автотесты (npm и npx на этой машине — с `NODE_OPTIONS=--use-system-ca`, иначе Kaspersky ломает сертификаты):

```bash
NODE_OPTIONS=--use-system-ca npm test               # расчёты, ссылка, листы, карты (node:test)
NODE_OPTIONS=--use-system-ca npx playwright test    # страница: desktop 1440 × 900 и phone 390 × 844
```

Оба должны быть зелёными перед коммитом. После этого — глазами на десктопе и на телефоне.

Новая версия рыси (Виталий доделал её в `C:\dev\metal-designer`): `NODE_OPTIONS=--use-system-ca npm run lynx -- 6` — номер версии из `plates-lynx6.js`; раскрой считается минутами. Потом посмотреть картинки в `lynx/` глазами (не пустые, рысь целиком, без панелей редактора) и закоммитить `lynx/`. `--rework <id>` — другая фигура для картинки «Переработка» (по умолчанию `lynx`, исходная гранёная).

## Как сайт публикуется

GitHub Pages собирает сайт из ветки `master`, из корня репозитория. После каждого `git push` он пересобирается примерно за минуту и открывается по адресу https://vitalishaklach.github.io/metal-designer-landing/. Репозиторий публичный: всё, что попадает в `master`, видят все. В `master` — только по команде Виталия.

Локально страница открывается так: `python tests/serve.py` из корня репозитория, затем http://localhost:8000/ (тот же сервер поднимают тесты Playwright). Ссылку на результат — в конце каждой задачи.

GitHub Pages разрешает браузерам держать файлы в кеше около 10 минут. Поэтому у скриптов и стилей стоит метка `?v=дата`: в `index.html` — у всех `<script>` и `<link rel="stylesheet">` (`md/*.js`, `vendor/`, `css/*.css`, `fonts/fonts.css`), в `demo.html` — у скриптов из `js/`. Поменялся любой такой файл — поменяйте дату во всех тегах этой страницы, иначе новая страница может получить старый скрипт и сломаться.

## Как мы работаем

Новая фича идёт по шагам: **брейншторм → спека → грилинг → план → `/to-tickets` → `/implement #N`**.

- Брейншторм — скилл `superpowers:brainstorming`, итог — спека в `docs/superpowers/specs/`.
- Грилинг — скилл `mattpocock-skills:grilling` по спеке; решения дописываются в спеку таблицей «Решения грилинга». Спека коммитится после грилинга.
- План — `superpowers:writing-plans`, в `docs/superpowers/plans/`.
- `/to-tickets` и `/implement` запускает только Виталий.

Одна задача в GitHub Issues — одна новая сессия Claude Code. В начале сессии берём задачу по номеру, читаем её и нужный документ дизайна, делаем, проверяем автотестами, на десктопе и на телефоне. В конце коммит, push и закрытие задачи.
